The practical decision

License Choro's original source and documentation under Apache-2.0. This supports open-source distribution, private use, modifications, and paid products while preserving attribution and patent terms.

  • Use Choro contributors only as a provisional attribution, not as a substitute for identifying the owner.
  • Keep authorship records; if a company later becomes the owner, use a written IP assignment.
  • Keep provider SDKs, vendored code, fonts, and logos under their existing terms.
  • No cloud-agent work is required for this licensing foundation.

What Apache-2.0 covers

It covers source and documentation created specifically for Choro unless a file says otherwise.

Penpot does not change Choro's licence

Choro Design is a self-hosted Penpot 2.16.2 service under MPL-2.0. MPL is file-level copyleft: modified Penpot files stay MPL, while separate Choro files can remain Apache-2.0.

The browser frontend counts as distribution.

Server-only code is not distributed merely because the service is online. HTML, CSS, and JavaScript sent to a browser or embedded web view are distributed, including minified JavaScript.

Before public access

  • Preserve Penpot's MPL and copyright notices.
  • Archive the exact 2.16.2 source plus every Choro change to MPL-covered files.
  • Link the Open source notice from the landing site and hosted Design UI.
  • Make corresponding source available without charge while that frontend is offered.
  • Operate hosted-account deletion, log retention, and backup deletion as stated in Privacy.

Read Mozilla's MPL 2.0 FAQ

Claude is a separate terms question

The Agent SDK is proprietary and is not converted to Apache-2.0 by Choro's root license. The current bridge passes a user's locally installed Claude Code executable to the SDK.

Private development is fine; public distribution is not cleared.

Anthropic's current guidance directs third-party Agent SDK products to API-key or supported cloud-provider authentication and does not permit routing Free, Pro, or Max credentials on users' behalf.

Before exposing this to customers

  • Use approved API or cloud-provider authentication, or
  • Get written confirmation from Anthropic for Choro's exact flow.

Read Anthropic's current legal guidance

Checklist before going public

  • Choose whether copyright is held personally or by a company and execute any needed written assignment.
  • Resolve the Claude authentication/distribution model.
  • Publish or archive corresponding source for the exact hosted Penpot frontend.
  • Expose the Open source notice from Choro Design and test the free source-request path.
  • Verify hosted Design deletion, backup expiry, and 30-day log retention.
  • Run the third-party license collector for the exact release build.
  • Review packages whose archives do not contain a conventional license file.
  • Include LICENSE, NOTICE, notices, and asset provenance.
  • Review product logos against current brand-usage rules.
  • Have counsel review the final commercial release if practical.
Current recommendation

Keep the repository private while building. The foundation is ready; complete this checklist immediately before launch.
