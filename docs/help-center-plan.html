How we will build it

  • Phase 1 · Core workflow. Getting started, working with agents, review and shipping, running projects and Preview.
  • Phase 2 · Deeper workflows. Band, Studio, Solo, tasks and docs.
  • Phase 3 · Supporting tools. Project context, Orbit, Quick Ask, voice, skills, Remote, and settings.
  • Phase 4 · Recovery and cross-links. Complete troubleshooting and connect every guide to its relevant recovery article. Add known fixes as earlier guides are written.
  • Article shape. Short answer → prerequisites → focused steps → expected result → common issues → related published articles. Overview and reference articles use the structure that fits their question.
  • Screenshot standard. Use actual demo screens with fictional project data. Show the relevant control and result; add useful alt text and captions. Use real iPhone captures for mobile instructions. No fabricated app UI or exposed credentials.
  • Verification. The video library is topic inspiration. Confirm current labels, supported integrations, provider setup, backup scope, and data-handling claims against the current implementation and app before publication.
  • Availability. Mark delegation as beta where relevant. Keep teams and cloud agents in the roadmap until available.
  • Existing content. Keep the published sample guide intact during this first article pass. Its eventual consolidation into Getting started is a later editorial decision.
