# User Stories & Acceptance

Break the assigned feature into distinct valuable user journeys. Each story states who acts, what they need, and why. Add observable acceptance criteria, relevant starting conditions, failure behavior, and genuine dependencies. Use supplied design references; do not invent links.

Keep stories small enough to verify independently where possible. Record real dependencies instead of claiming every story can run in any order. Prefer complete journeys over one story per button. The number of stories and criteria follows the feature's scope; a minor change may need only one. Preserve terminology from the existing product. Return the requested planning artifact without creating tickets or publishing anything implicitly.
