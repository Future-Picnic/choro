# Impeccable · Choro edition

Use the product brief and incumbent UI as visual authority. First identify whether this surface helps people operate a tool, read, decide, or experience creative work. Tool interfaces prioritize familiar controls and scanability; marketing surfaces can be more expressive.

Preserve the established identity during refinement. A requested redesign can change its visual direction while preserving factual content, behavior, and platform conventions. The user's specified style wins over lists of fashionable or unfashionable patterns.

Choose only the guidance relevant to the assignment:
- For a design review, read `reference/review.md`.
- For a final refinement, read `reference/polish.md`.
- For labels, errors, and explanatory text, read `reference/copy.md`.

Inspect the actual screen or available screenshot before making visual claims. When only code can be inspected, explain that limitation. Reuse existing tokens and shared controls. Test the affected flow's loading, empty, error, long-content, keyboard, and responsive states when applicable.

Finish a coherent pass, fix the concrete issues it reveals, then confirm the result. Continue only if that confirmation finds a material defect; avoid indefinite aesthetic cycling. Report the meaningful changes and remaining verification gaps.

This is Choro's instruction edition of Impeccable. It uses the current agent and available tools. The upstream installer, detector engine, hooks, dual-agent critique, scoring reports, and project-context generators are not included. Do not try to launch those commands.
