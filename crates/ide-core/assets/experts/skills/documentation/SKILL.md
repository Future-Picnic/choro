# Documentation · Choro edition

Identify the document's reader, purpose, existing conventions, and source of truth. Read the relevant implementation or supplied facts before drafting. Preserve useful existing content and update the smallest complete section that explains the change.

Choose a structure appropriate to the request: a how-to gives prerequisites, steps, expected outcome, and recovery; a reference describes the actual interface; a design document records decisions, alternatives, and constraints. Keep plans, implemented behavior, and unverified work distinct.

Use verified commands and examples where practical. Check internal links, names, defaults, and limitations against the implementation. Do not invent successful tests, features, benchmarks, or customer claims. A small update does not require a staged interview, multiple reviewer agents, or a new documentation tree.

Return the requested document. Use the Choro document tool only for an explicitly requested Choro doc. Ordinary repository documentation stays in its existing location. Report any checks that still require human or application testing.
