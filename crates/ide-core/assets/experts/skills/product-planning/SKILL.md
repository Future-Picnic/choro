# Product Planning

Identify the user problem, intended audience, desired outcome, and constraints from the supplied context. Check the existing product before proposing new capabilities. Ask only about decisions that materially affect the work and cannot be inferred.

For a small feature, describe the outcome, included and excluded behavior, acceptance criteria, important edge cases, dependencies, and open decisions. Distinguish known facts from assumptions. Tie each proposed capability to the problem it solves. Do not invent market research, success metrics, delivery dates, or stakeholder requirements.

For an explicitly requested PRD, expand into summary, goal, audience, value, solution, assumptions, and release scope. Use technical detail only where it records a necessary interface or implementation constraint. Use an existing document if the project has one; produce a file only when the assignment calls for it. Return an implementable plan without starting implementation.
